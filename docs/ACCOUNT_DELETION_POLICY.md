# Account Deletion Policy

## 1. Overview

This policy describes the account deletion process for AI News Digest, including what data is removed, what is retained, and how users can request deletion.

## 2. User Rights

Users have the right to:
- Request deletion of their account
- Know what data will be deleted and what will be retained
- Receive confirmation when deletion is complete

**NOT YET ENFORCED:**
- Self-service account deletion through account settings
- Data portability (download your data before deletion)

## 3. Deletion Methods

### 3.1 Administrator-Initiated Deletion (CURRENT IMPLEMENTATION)

**VERIFIED:** Administrators can delete user accounts via the API:
```
DELETE /api/v1/admin/users/{user_id}
```

This is a hard delete - the user record is permanently removed from the database.

### 3.2 Self-Service Deletion (NOT YET ENFORCED)

**NOT IMPLEMENTED:** The policy describes self-service deletion through:
1. Navigating to Account Settings
2. Selecting "Delete Account"
3. Confirming the deletion with their password
4. Acknowledging the consequences of deletion

**CURRENT STATE:** The DashboardPage (`frontend/src/pages/dashboard/DashboardPage.tsx`) does not contain a "Delete Account" option. There is no self-service deletion endpoint.

### 3.3 Email Request (NOT YET ENFORCED)

**NOT IMPLEMENTED:** Users may request deletion by emailing the support address. Identity verification is required before processing.

## 4. Data Removed Upon Deletion

**VERIFIED:** When an admin deletes a user, the following data is permanently removed:
- Email address
- Password hash
- Account profile
- User preferences
- Authentication tokens (by virtue of user deletion)

## 5. Data Retained After Deletion

The following data may be retained in anonymized form:
- Anonymized usage statistics
- Aggregated analytics
- Legal compliance records

## 6. Data NOT Affected by Account Deletion

**VERIFIED:** Deleting a user account does NOT affect:
- Articles in the database (these are sourced from RSS feeds, not user data)
- Digests generated by the system (these are system-generated content)
- Other users' data
- System logs (which are anonymized)

## 7. Grace Period (NOT YET ENFORCED)

**NOT IMPLEMENTED:** The policy describes a 7-day grace period after account deletion:
- During this period, the account can be restored by contacting support
- After 7 days, deletion is permanent and irreversible
- The user's email address becomes available for new registration after 30 days

**CURRENT STATE:** Deletion is immediate and irreversible. There is no grace period or soft-delete mechanism.

## 8. Verification Process (NOT YET ENFORCED)

**NOT IMPLEMENTED:** The policy describes:
1. Password re-entry for identity verification
2. Confirmation email sent to registered address
3. Deletion processed only after email confirmation
4. Final confirmation email when deletion is complete

**CURRENT STATE:** Admin deletion requires admin authentication (JWT token). No additional verification or email confirmation is sent.

## 9. Technical Implementation

**CURRENT IMPLEMENTATION:**
Account deletion is implemented in `src/ai_news_digest/api/v1/routes/admin.py`:
```python
@router.delete("/api/v1/admin/users/{user_id}", ...)
async def delete_user(user_id, container, ...):
    user = await container.user_repository.get_by_id(user_id)
    await container.user_repository.delete(user_id)
```

This is a **hard delete** - the user record is permanently removed.

**NOT YET ENFORCED:**
- Soft delete mechanism
- Grace period implementation
- Email confirmation flow
- Self-service deletion endpoint

## 10. Compliance

This policy is designed to comply with:
- GDPR Article 17 (Right to erasure)
- CCPA (Right to delete)
- Other applicable data protection regulations

## 11. Contact

For questions about account deletion or to request deletion, contact the system administrator.
