## 2. Production Workflow Verified

The following execution path was traced through the actual implementation:

```
Trusted Sources (Source.status == VERIFIED, is_active == True)
      ↓
SourceRepository.list_enabled() filters by VERIFIED + is_active
      ↓
RSS ingestion (FeedparserFetcher)
      ↓
URL normalization (CanonicalUrl)
      ↓
SSRF validation (validate_rss_http_url: scheme, DNS, IP classification, per-hop redirect re-validation)
      ↓
Safe HTTP fetching (SsrfHttpArticleFetcher: timeout, response-size cap, redirect limits)
      ↓
Article extraction (StdlibHtmlExtractor + ContentCleaner + ContentQualityValidator)
      ↓
RSS fallback (extraction failure preserves RSS summary/content)
      ↓
Article persistence (ArticleRepository.create with canonical URL deduplication)
      ↓
Deduplication (in-feed seen_urls + database get_by_url check)
      ↓
AI analysis (AI_ENABLED=false → safe skip; AI_ENABLED=true → ProviderManager with health/circuit/quota)
      ↓
Claims / Evidence (ExtractClaimsUseCase, guarded by AI_ENABLED)
      ↓
Contradiction detection (DetectClaimConflictsUseCase)
      ↓
Story clustering (ClusterArticlesUseCase)
      ↓
Story activity / events (DetectStoryActivityUseCase, GenerateStoryTimelineUseCase)
      ↓
Trends (DetectTrendsUseCase)
      ↓
Ranking (StoryRankingEngine + TopStorySelector)
      ↓
Top Story (selected during ranking)
      ↓
Digest generation (GenerateDigestUseCase / GenerateIntelligentDigestUseCase)
      ↓
Public API (FastAPI routes under /api/v1/public/)
      ↓
Frontend (React/TypeScript/Vite SPA)
```

## 7. Security

### Verified
- **Authentication:** JWT with HS256, bcrypt password hashing, constant-time dummy hash on failed login
- **Authorization:** Admin RBAC on all `/api/v1/admin/*` routes
- **IDOR protection:** Ownership checks on all `/me/*` endpoints
- **CORS:** Fail-closed in production (empty allowlist), explicit allowlist in dev/staging
- **Security headers:** CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy
- **Rate limiting:** Redis-backed with configurable limits and brute-force lockout
- **SSRF protection:** Scheme check, DNS resolution, IP classification, per-hop redirect re-validation, response-size caps, timeout bounds
- **Request validation:** Max body size middleware, Pydantic validation
- **Error sanitization:** Production 500s return generic messages
- **Secret handling:** No secrets in tracked files, `.env`/`.env.staging` gitignored
- **JWT secret validation:** Rejects weak defaults and placeholder patterns in production

### Remaining limitations
- No JWT refresh tokens (stateless access tokens only, 60-minute expiry)
- No token revocation blacklist
- `.env.staging` contains staging credentials in working tree (gitignored, not tracked)

2. **No real AI provider credentials available** — AI provider implementations verified through code review; `AI_ENABLED=false` path verified through tests.
3. **Production deployment not verified** — No production credentials or infrastructure access available. Deployment configuration reviewed.
4. **Windows test environment limitations** — 5 integration-style tests require Docker/testcontainers and fail on Windows due to pytest-asyncio scope mismatch. These tests pass in Linux CI environments.
5. **`.env.staging` contains credentials** — While gitignored and not tracked, should be rotated as a precaution.
6. **Evaluation service N+1** — `run_evaluation` calls `list_by_cluster_id` per cluster and `list_evidence_by_claim_id` per claim in a bounded background task (limits: 500 claims, 200 clusters). Documented as acceptable for v1.0.
7. **Semantic search architecture** — Lexical candidate retrieval followed by in-process embedding-based reranking. No vector database or ANN index. Documented as bounded and correct for v1.0.
8. **Pre-existing MyPy errors** — 67 errors in 20 source files (not introduced by this validation).
9. **Pre-existing Ruff issues** — 257 issues in source files (not introduced by this validation).
